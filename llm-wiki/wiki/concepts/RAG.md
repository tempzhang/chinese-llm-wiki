# RAG（检索增强生成）

## 一句话定义

RAG（Retrieval-Augmented Generation）是一种通过从外部知识库检索相关文档片段来增强大语言模型回答质量的技术。

## 核心要点

- 核心流程：用户提问 → 向量检索 → 返回相关文档片段 → LLM 基于片段生成回答
- 优势：无需微调模型，即可让 LLM 访问外部知识
- 局限：分块策略导致上下文断裂，容易产生幻觉
- LLM Wiki 是另一种解决思路

## 详细说明

### 基本流程

1. **文档预处理**：将知识库文档切分为适当大小的文本块（chunk）。
2. **向量化**：将每个文本块通过 embedding 模型转换为向量。
3. **存储**：向量存入向量数据库（如 Pinecone、Chroma、Milvus）。
4. **检索**：用户提问时，将问题向量化，在数据库中搜索最相似的 K 个文本块。
5. **生成**：将检索到的文本块作为上下文注入 LLM，生成回答。

### 主要局限

1. **上下文断裂**：分块可能把一个完整概念切成碎片，LLM 看不到全局。
2. **检索噪声**：相似度检索不一定返回最相关的内容，可能引入无关信息。
3. **缺乏推理**：RAG 是"找到就塞"，无法做深层推理和交叉链接。
4. **难以审计**：用户不知道 LLM 用了哪些文档片段，难以验证真实性。
5. **维护困难**：文档更新后需要重新分块和索引。

### RAG 与 LLM Wiki 的关系

- [[LLM Wiki]] 是 RAG 的替代思路：不是实时分块检索，而是预先编译知识。
- 两者可以互补：RAG 适合海量非结构化文档；LLM Wiki 适合需要深度理解的核心知识。
- 详细对比见 [[RAG 与 LLM Wiki 对比]]。

## 适用场景

- 大量非结构化文档的问答
- 客服知识库
- 企业内部文档搜索
- 法律/医疗等需要大量引用的领域
