# 知识编译

## 一句话定义

知识编译是 LLM Wiki 的核心工作方式——AI Agent 阅读原始资料后，将其消化提炼为结构化、可追溯的 Wiki 页面。

## 核心要点

- 不是"索引"（RAG 的方式），而是"编译"
- 编译过程包含：理解 → 提炼 → 结构化 → 交叉链接
- 输出是人类和 LLM 都能理解的高质量知识页面
- 原始资料保留在 `raw/`，编译结果在 `wiki/`

## 详细说明

### 为什么叫"编译"

借用软件工程的类比：
- 源代码（原始资料）→ 编译器（AI Agent）→ 目标代码（Wiki 页面）
- 编译器做的不只是复制粘贴，而是理解、优化、链接
- 编译后的产物结构清晰、可复用

### 编译流程

1. **输入**：`raw/` 中的原始资料（网页、视频、PDF 等）
2. **解析**：AI Agent 理解资料内容
3. **提取**：识别关键概念、实体、流程、观点
4. **组织**：按照 Wiki 页面的标准结构编写
5. **链接**：使用 `[[双向链接]]` 建立知识网络
6. **输出**：`wiki/` 中的结构化页面

### 与 RAG 索引的区别

| 维度 | RAG 索引 | 知识编译 |
|------|----------|----------|
| 方式 | 分块 + 向量化 | 理解 + 重写 |
| 输出 | 文本片段 | 完整页面 |
| 上下文 | 断裂 | 完整 |
| 链接 | 无 | 双向链接 |
| 可读性 | 低（碎片） | 高（结构化页面） |
| AI 耗时 | 低（索引时） | 高（编译时） |
| 回答质量 | 依赖检索精度 | 稳定可控 |
